# QWOP-AI · 用 PPO 教会小人跨栏并跳远

一个用 **PPO（Proximal Policy Optimization）** 强化学习训练 **QWOP** 的端到端项目。
通过浏览器内桥接脚本直接读取游戏物理状态、合成按键、同步快进，让智能体在
**带跨栏 + 沙坑跳远** 的 QWOP 变体里尽快跑到终点。

> 🎮 这是 QWOP 的**跨栏 + 沙坑跳远**变体：先跑过 x≈500（约 50 米）处的栏架，
> 再在沙坑完成跳远，落地即通关（"X metres in Y seconds"）；中途摔倒则失败。

---

## ✨ 特性

- **状态直读，不靠像素**：直接读取 Box2D 的 12 个刚体状态（位置/角度/速度），用小型 MLP 即可训练，无需 CNN。
- **同步快进**：劫持 `requestAnimationFrame` + 虚拟时钟，单环境可达 ~20× 实时速度，多环境并行更快。
- **可调奖励**：`reward_config.json` 实时改权重（前进 / 摔倒 / 超时 / 跨栏站立 / 跳远距离），训练中保存即生效。
- **4 套可视化**：实时仪表盘、观战 + HUD 数据叠加、训练后分析图、姿态骨架。

---

## 🧰 环境要求

- Python 3.10+
- **默认物理后端**：`box2d`（纯 Python Box2D，`pip install box2d`），无需浏览器，速度极快
- **浏览器后端（可选）**：[Playwright](https://playwright.dev/) 浏览器内核（Chromium / Edge / Chrome 任一）
- 一个现代浏览器（浏览器后端观战 / 仪表盘用）

## 🚀 快速开始

```bash
# 1. 克隆
git clone https://github.com/GUAJIUKE/qwop-ai.git
cd qwop-ai

# 2. 创建虚拟环境并安装依赖
python -m venv venv
venv\Scripts\activate        # Windows
#   source venv/bin/activate  # macOS/Linux
pip install -r requirements.txt

# 3. 安装 Playwright 浏览器

# 4. 拉取并打补丁游戏运行时 (自动从官方源下载, 见下方版权说明)
python fetch_game.py

# 5. 开始训练
python train.py --n-envs 8 --timesteps 3000000

# 6. 随时观战 (另开终端)
python watch.py --mode pose          # 叠加人形骨架看跑姿
python dashboard.py                  # 启动实时仪表盘 http://127.0.0.1:8765
```

> 💡 脚本内置"依赖自检"：若当前 Python 缺少依赖，会自动用虚拟环境重跑，无需手动切换解释器。

## 🧱 两种训练后端（速度关键）

训练瓶颈**不在神经网络，而在环境仿真**：原版环境用 Playwright 驱动浏览器跑 Box2D 物理，
每次 `step()` 都要一次跨进程 `page.evaluate` 往返，单环境约 **20× 实时**。智能体的 MLP
（`[256,256]`）算力相对可忽略。

本项目提供两种后端，由 `train.py --backend` 切换：

| 后端 | 原理 | 速度（单环境） | 保真度 |
|---|---|---|---|
| `browser`（原版） | Playwright 驱动真实 QWOP 游戏 | ~20× 实时 | 100% 原版游戏 |
| **`phys`（默认）** | 纯 Python Box2D 复刻 12 刚体 ragdoll，进程内运行 | **~数百× 实时** | QWOP 风格复刻（标准做法） |

`phys` 后端去掉了浏览器 + Playwright 的全部开销，单环境可达 **约 870× 实时**（实测约 2.6 万物理帧/秒），
比原版快 **40 倍以上**，且 obs(88)/动作(9)/奖励/跨栏/沙坑接口与原版**完全一致**，所以
`train.py` / `watch.py` / `analyze.py` / 仪表盘都无需改动即可切换。

> ⚠️ **保真度说明**：`phys` 后端是用 Box2D 从头复刻的 QWOP 风格双足 ragdoll（相同的 12 刚体、
> Q/W/O/P 肌肉控制、跨栏与沙坑机制），而非官方游戏二进制。这是 QWOP-AI 研究的**通用做法**
> （原版游戏代码混淆、强耦合浏览器，难以高速批量仿真）。若需与原版 1:1 对照，用 `--backend browser`。
> 为让底座可学，`phys` 后端对躯干施加了"核心稳定"PD 力矩（模拟核心张力），因此平衡难度低于原版，
> 但前进/跨栏/跳远仍是需学习的操控任务。

```bash
# 默认物理后端（极快，推荐）
python train.py --n-envs 8 --timesteps 3000000

# 对照：原版浏览器后端（忠实但慢）
python train.py --backend browser --n-envs 8 --timesteps 3000000
```

观战同样支持两种后端：

```bash
python watch.py --backend phys   --mode pose   # matplotlib 实时骨架（无需浏览器）
python watch.py --backend browser --mode pose  # 浏览器画面 + HUD/骨架叠加

### 🚀 速度优化（2026-07-30）：从 132s 压缩到 65.5s

通关后第二阶段目标是**冲击最快速度**（QWOP 世界纪录约 33 秒）。把奖励从"到达终点"
改为"尽快到达"后，速度提升显著：

| 阶段 | 最快耗时 | 速度 | 关键改动 |
|---|---|---|---|
| 旧物理 + 距离奖励（基线） | 132.4s | 0.73 m/s | 终点奖励为主，无速度信号 |
| 新物理 + 速度奖励（600k 验证） | 88.2s | 1.13 m/s | 每步前向速度奖励 + 放开关节电机速度上限/扭矩 |
| **新物理 + 速度奖励（2M 全量）** | **65.5s** | **1.53 m/s** | 同上，2M 步收敛（10/10 确定性通关，每局 655 步） |

> 核心改动：`qwop_phys.py` 新增**每步前向速度奖励**（`velocity_coeff`）、放开电机速度
> 上限 `CLAMP 12→18` 与髋/膝扭矩；`reward_config.json` 调高时间惩罚并启用速度系数。
> 当前 65.5s 仍是世界纪录（33s）的约 2 倍，下一步将更激进地放开物理上限（更大步幅、
> 更高扭矩、允许前倾奔跑姿态）继续逼近。

### 🏁 激进物理放开（2026-07-30）：52.0s / 1.92 m/s

在 65.5s 基础上进一步放开物理：步幅前伸 `HIP_TARGET -0.6→-0.95`、屈膝 `1.0→1.2`，
电机速度上限 `CLAMP 18→26`、髋/膝扭矩 `42k→65k / 22k→38k`，核心 PD 略放松允许前倾，
速度奖励系数 `0.3→0.6`。2M 步从头训练后：

| 阶段 | 最快耗时 | 速度 |
|---|---|---|
| 激进物理 + 速度奖励（2M 全量） | **52.0s** | **1.92 m/s** |

> 较基线（132.4s）提速 **2.5 倍**，较上一版（65.5s）再减 13.5 秒。10/10 确定性通关，
> 每局固定 520 步。模型：`models/ppo_qwop_final.zip`（恢复验证 52.6s / 1.90 m/s）。
> 后续若继续逼近 33s 世界纪录，需突破当前"快走"步态上限（真实奔跑含腾空相，当前
> 位置式控制 + 始终开启核心稳定的 ragdoll 难以实现），可能要重构动力学。

### 🔚 速度上限探测（2026-07-30）：52s 即天花板

继续加码物理（在 52s 配置上 `CLAMP 26→32`、髋扭矩 `65k→85k`、步幅 `→-1.05`、核心 `KP→35000`、
速度奖励 `0.6→0.9`）后重训 2M 步，结果反而 **退化到 55.5s / 1.80 m/s**——印证 `CLAMP>26` 已
越过效率拐点。结论：**52s 是这套"位置式控制 + 始终核心稳定"ragdoll 设计的实用速度上限**。

| 物理激进度（CLAMP） | 最快耗时 | 速度 |
|---|---|---|
| 18（首轮速度优化） | 65.5s | 1.53 m/s |
| **26（最优）** | **52.0s** | **1.92 m/s** |
| 32（过冲） | 55.5s | 1.80 m/s |

> 各版本模型已归档：`models/speed_v1_65s/`（65s）、`models/speed_v2_52s/`（52s 原始）、
> `models/speed_v3_55s/`（55s 过冲）。当前 `models/ppo_qwop_final.zip` 为最优 52s 配置。
> 要到 33s 世界纪录，必须重构动力学（真实奔跑含腾空相，需放开核心稳定、引入飞行态）。

### 🚫 奔跑重构尝试（2026-07-30）：前倾/软核心无效，52s 仍是上限

为冲 33s 世界纪录，重构核心稳定逻辑，使其能"前倾奔跑"而非"焊死直立快走"：
- 软核心 + 前倾（`CORE_KP 40000→22000`，目标前倾 `CORE_LEAN=-0.4`，`CLAMP 26→34`）：2M 步 → **71.0s / 1.41 m/s**（比 52s 更慢，躯干软塌失稳）
- 强核心 + 稳定前倾（`CORE_KP→45000`，`CORE_LEAN=-0.5`，`CLAMP→30`）：300k 验证 → **70.9s / 1.41 m/s**

| 配置 | 最快耗时 | 速度 |
|---|---|---|
| 直立 + CLAMP=26（52s） | **52.0s** | 1.92 m/s ← 最优 |
| 直立 + CLAMP=32 | 55.5s | 1.80 m/s |
| 前倾 -0.4 + 软核心 + CLAMP=34 | 71.0s | 1.41 m/s |
| 前倾 -0.5 + 强核心 + CLAMP=30 | 70.9s | 1.41 m/s |

> **结论**：问题不在核心软硬，而在"前倾"这一动作本身对当前"位置式关节控制 + 每帧核心 PD 扶正"
> 的 ragdoll 无效甚至有害。奔跑需要**腾空相**（双脚离地），而本模型核心每帧都在扶正、腿是位置式
> 受限摆动——本质上只能"快走"，无法产生飞行相。因此 **52s（1.92 m/s）就是该设计的速度上限**。
> 仓库已恢复至 52s 最优配置（`qwop_phys.py` 常量、`reward_config.json`、`ppo_qwop_final.zip` 均已回滚），
> 失败产物归档于 `models/speed_v4_lean_71s/`。
>
> **要到 33s（3.0 m/s，需再快 ~1.6 倍）必须做更彻底的动力学重构**，候选方向：
> 1. 把肌肉控制从"位置式目标角"改为"力矩/力驱动"（PD 高增益 + 无速度钳制），让腿能自由甩动产生弹跳；
> 2. 核心稳定改为"条件式"——仅在接近摔倒时强力扶正，支撑/摆动期放手让躯干做弹道运动（产生腾空相）；
> 3. 降低躯干转动惯量/质量，使整体能更快弹跳。
> 以上均属较大改动且存在学不会/失稳风险，需单独立项。

### 🔬 深度动力学重构（2026-07-31）：两条路线均未突破，52s 结论成立

按上节列出的候选方向真正做了两轮重构实验，结果**都比 52s 慢**。这里完整记录，避免日后重走。

**v1 — 条件式核心 + 放开速度钳制**（`QWOP_RECON=1`）

不再每帧把躯干焊死在直立位，改为：`|躯干角| < 0.70 rad` 时只施加弱弹簧
（`CORE_WEAK_KP=8000`，目标前倾 `0.25 rad`），超过阈值才切换强 PD 防摔；
同时 `CLAMP 26→55`，并下调躯干/头密度（`0.8→0.55` / `0.5→0.40`）降低转动惯量。
被动平衡计算显示躯干会自然停在约 `0.33 rad` 前倾——正是奔跑所需的质心前移姿态。

| 训练量 | 最快耗时 | 速度 |
|---|---|---|
| 1M 步 | 59.6s | 1.68 m/s |
| 3M 步 | 57.1s | 1.75 m/s |

**v2 — 在 v1 基础上把肌肉改为力矩驱动**（`QWOP_RECON=1 QWOP_TORQUE=1`）

分析 v1 失败原因时发现一个关键点：位置伺服下达的电机速度是
`K_POS × (target − angle) ≈ 25 × 0.95 ≈ 24`，**真正的限速项是 `K_POS` 而不是 `CLAMP`**。
所以 v1 把 `CLAMP` 从 26 抬到 55 其实几乎没改变腿速，只是多了个前倾姿态。
v2 因此改为：按下键时以远超可达的目标速度（`TORQUE_DRIVE_SPEED=60`）朝关节限位猛推，
等效恒定最大扭矩驱动（爆发性蹬伸）；松开键时仍用位置伺服温和回中。

| 训练量 | 最快耗时 | 速度 |
|---|---|---|
| 2M 步 | 67.8s | 1.47 m/s |

**汇总对比**

| 配置 | 最快耗时 | 速度 |
|---|---|---|
| **直立锁定 + 位置伺服（基准）** | **52.0s** | **1.92 m/s** ← 仍是最优 |
| v1 条件式核心 + CLAMP=55（3M） | 57.1s | 1.75 m/s |
| v2 v1 + 力矩驱动肌肉（2M） | 67.8s | 1.47 m/s |

> **结论**：放开核心约束确实让躯干能前倾了，但 agent 并没有因此学会奔跑，而是收敛到
> 一种**更费力的前倾快走**——10 局评估步数完全一致（571 / 678 步），说明策略已充分收敛，
> 不是训练不足。给腿更大的爆发力（v2）反而更慢：失去位置约束后蹬伸时机难以协调，
> 策略退化为更保守的小步幅。
>
> 更根本的原因可能在于**动作空间与时间分辨率**：QWOP 只有 4 个二值按键、每步 0.1s，
> 而真实奔跑的腾空—着地相位切换需要更精细的时序控制。在这个动作空间下，
> 「稳定快走」很可能就是 PPO 能找到的全局较优解。要冲 33s 恐怕需要换更细的控制频率
> 或引入步态先验（如相位振荡器 CPG），已超出本项目当前范围。
>
> 两条路线的代码都保留在 `qwop_phys.py` 中，用环境变量开启：
> `QWOP_RECON=1` 启用 v1，再加 `QWOP_TORQUE=1` 启用 v2，**默认均关闭**（即 52s 最优配置）。
> 模型归档于 `models/run_recon/`、`models/run_torque/`。

## 🏃 游戏机制

| 要素 | 说明 |
|---|---|
| 终点 | 100 米（躯干世界坐标 x / 10） |
| 跨栏 | 栏架位于 `x ≈ 500`（约 **50 米**），需站立通过，否则只能爬行 |
| 跳远 | 沙坑处 `jumpLanded` 标志置位即完成跳远，落地距离计入成绩 |
| 失败 | `fallenEnding`（摔倒）；成功为 `jumpEnding`（"X metres in Y seconds"） |

## 🎯 奖励设计（`reward_config.json` 可调）

| 组件 | 公式 | 默认权重 |
|---|---|---|
| 前进奖励 | `Δmetres × forward_per_metre` | `1.0` |
| 摔倒惩罚 | 摔倒时 `−fall_penalty` | `5.0` |
| 超时惩罚 | 达 `max_steps` 未完成 `−timeout_penalty` | `5.0` |
| 跨栏站立加成 | 过栏且躯干近乎直立 `＋hurdle_stand_bonus`，否则爬行 `＋hurdle_crawl_bonus` | `8.0 / 1.0` |
| 跳远距离加成 | `jumpLanded` 时 `＋jump_distance_bonus × 最终米数` | `1.0` |
| 通关奖励 | 跳远落地额外 `＋success_terminal_bonus` | `50.0` |

训练中直接编辑 `reward_config.json` 保存即可生效（环境按文件修改时间自动重载），
或在仪表盘底部拖滑块实时调整。

### 不稳定性分析（重要！）

> **为什么训练后期还会出现 0~1 米的成绩？** 完整分析见 [docs/INSTABILITY_ANALYSIS.md](docs/INSTABILITY_ANALYSIS.md)

**一句话结论：不是退步，是 PPO 探索机制的副作用。**

| 因素 | 影响 | 修复难度 |
|---|---|---|
| Action 0（空操作）被随机探索采样到 → 立即摔倒 | 占后期失败的 **80%+** | 改 1 行代码 |
| 熵系数 ent_coef=0.01 未衰减 → 后期仍有 ~1% 随机动作 | 占 **15%** | 加 1 个参数 |
| 学习率未衰减 → 策略震荡无法收敛到保守策略 | 占 **5%** | 加 1 个参数 |

详细数据、分段分析、修复方案和预期效果见完整报告。

### 学习曲线

![学习曲线](analysis/learning_curve.png)

### 综合分析

![综合分析](analysis/qwop_analysis.png)

6 个子图展示：
1. **距离趋势**：滚动均值从 0→100m，目标线 100m 已突破
2. **奖励曲线**：从 -14 飙升到 ~250，信号健康无震荡
3. **回合长度**：后期稳定在 1700~1900 步/回合（接近 max_steps=2000 上限）
4. **跨栏率/通关率**：跨栏率接近 100%，通关率持续爬升
5. **通关距离分布**：集中在 99~101m（13 个已通关回合）
6. **动作分布**：9 个动作均有使用，a2/a7/a8（前进组合键）使用最多

![仪表盘](docs/dashboard_100m_screenshot.png)

仪表盘实时显示：训练步数、最远纪录、跨栏成功率、FPS、学习曲线、最近 60 回合距离柱状图、动作分布热力图，以及底部 8 个可拖动的奖励调节滑块。

### 关键发现

- **收敛极快**：仅用计划步数的 ~7% 就达到 100m，10% 达到 103.54m，说明状态直读 + 组合键动作空间的设计非常高效
- **跨栏是关键分水岭**：约 12 万步前卡在 20~30m（"跪地蹭"局部最优），一旦学会过栏就迅速冲到 80m+
- **奖励设计有效**：跨栏站立加成(+8) vs 爬行加成(+1) 的差异化让智能体优先学站立过栏
- **后期 0m 回合 = 探索噪声**：777 回合中 98% 的失败集中在早期（阶段 1-4），后期实际失败率仅 7%。根因是 Action 0（空操作）被 PPO 随机探索采样 → 立即摔倒。详见[不稳定性分析](docs/INSTABILITY_ANALYSIS.md)
- **修复方案明确**：移除 Action 0 + 熵衰减 + 加重摔倒惩罚，预计可将后期失败率从 3~7% 降到 <0.5%
